# Design Spec: Structured Cover Letter Harness (Why Company/Me/Now)

- **Date:** 2026-06-25
- **Status:** Approved
- **Author:** Gemini CLI
- **Approach:** Structural Heading Parsing (Approach A)

---

## 1. Overview & Objectives

Currently, `cv-tailor` generates a cover letter that consists of 3–5 free-flowing paragraphs following a standard introduction -> body -> closing narrative. 

To improve the specificity, structure, and professional impact of the generated cover letters, we are transitioning to a strict **Three-Question Template**:
1.  **Why `<company-name>`?** (Connecting motivation/mission directly to the target firm)
2.  **Why me?** (Highlighting concrete, quantified proof points from past projects)
3.  **Why now?** (Aligning career timing, goals, and logistics like availability/relocation)

Each of these three sections will be structured under a Markdown H2 heading. This design document outlines how we will update the house guides, LLM system prompts, LaTeX compilation engine, and evaluation harness to seamlessly support this structured template without breaking backward compatibility or affecting CV generation.

---

## 2. Core Architecture & Component Updates

### 2.1. Cover Letter Guide Update (`data/guides/how-to-write-a-cover-letter.md`)

We will update the guide to explicitly mandate this structured format. The new structure guidelines:

*   **Header `## 1. Why <company-name>?`**
    *   State the role. State one clear, genuine hook connecting professional motivation/personal interest to the company's mission/problem. Avoid cliché openings.
*   **Header `## 2. Why me?`**
    *   Cites 1-2 concrete, quantified proof points from the candidate's portfolio. Connects skills developed back to the target role.
*   **Header `## 3. Why now?`**
    *   Restates interest and fits logistics (availability, relocation/work-authorization) into a cohesive final paragraph.

### 2.2. Prompt Templates Update (`data/prompts/cover.md` & `engine/render.py` fallback)

We will update the LLM prompt to strictly enforce formatting rules:
*   Use Markdown H2 headings for the three sections:
    1.  `## 1. Why [Company]?` (or localized/translated version, e.g. `## 1. Warum [Company]?` in German)
    2.  `## 2. Why me?` (`## 2. Warum ich?`)
    3.  `## 3. Why now?` (`## 3. Warum jetzt?`)
*   No other headings, titles, salutations, or sign-offs should be generated by the model.

### 2.3. LaTeX Rendering Updates (`engine/latex.py`)

To render Markdown headings beautifully into the standard `coverletter.cls` template (which does not support headings natively), we will intercept headings in `_letter_block` in `engine/latex.py`:

```python
def _letter_block(body: str, company: str, attn: str, salutation: str,
                  signoff: str, name: str) -> str:
    # Split body into blocks by double line breaks
    blocks = [b.strip() for b in re.split(r"\n\s*\n", body.strip()) if b.strip()]
    formatted_blocks = []
    
    for block in blocks:
        # Check if the block is a Markdown heading
        heading_match = re.match(r"^#{2,3}\s+(.+)$", block)
        if heading_match:
            # Format heading as standard LaTeX bold inline text with vertical spacing
            title = inline(heading_match.group(1))
            formatted_blocks.append(f"\\vspace{{8pt}}\\noindent\\textbf{{{title}}}\\par\\vspace{{3pt}}")
        else:
            # Format as normal paragraph text
            formatted_blocks.append(inline(" ".join(block.splitlines())))
            
    paras = "\n\n".join(formatted_blocks)
    return "\n".join([
        "\\recipient{%s}{%s}{}" % (inline(company), attn),
        "",
        "\\opening{%s}" % inline(salutation),
        "",
        paras,
        "",
        "\\closing{%s}{%s}" % (inline(signoff), inline(name)),
    ])
```

This transforms headings into clean, inline LaTeX text blocks, completely bypassing escaping issues and preserving the original spacing of the cover letter.

### 2.4. Evaluation Harness Updates (`tests/experiments/harness.py` & `evaluate.py`)

To ensure we can evaluate both new and old cover letters (backward compatibility), we will modify `cover_metrics`:
1.  **Heading Check**: Check if the cover letter contains any lines starting with `## ` or `### `.
2.  **Scoring Adjustments**:
    *   If headings are present: Ensure there are exactly 3 headings matching the pattern (Why Company, Why Me, Why Now), and that the paragraph count matches.
    *   If headings are absent (old gold references): Fall back to the legacy 3-5 paragraph count scoring to prevent breaking existing tests.
3.  **New Quality Metrics**: Introduce a binary `cl_has_headings` metric (5% weight) and re-weight metrics slightly to reward structured formatting.

---

## 3. Verification & Testing Strategy

*   **Unit Tests**: Run `pytest tests/test_experiments.py` to verify that existing test suites pass.
*   **Dry Run Rendering**: Run `cv-tailor pdf <slug>` on a test application directory to ensure that both the Markdown files and LaTeX compiled PDFs look visually stunning and correct.
*   **Benchmark Validation**: Run `python tests/experiments/run.py` to regenerate a train case with the new prompt, then run `python tests/experiments/evaluate.py --no-judge` to ensure scoring is accurate.
